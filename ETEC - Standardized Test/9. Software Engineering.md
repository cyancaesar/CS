# SKU 9.1

**Software Processes, Software Management and Requirements Engineering**

Topics:

1. Software interaction with various systems including information management, embedded, process control, and communications systems.
2. Different process models (e.g., waterfall, iterative, and agile).
3. Phases of software lifecycle and its deliverables.
4. Software risks.
5. Key components of a use case.
6. Requirements model for a simple software system.
7. Fundamental techniques used for requirements elicitation.
8. Key components of a data model (e.g., class diagrams or ER diagrams).
9. Functional and non-functional requirements for a software system.

SLOs:

9.1.1: Describe how software can interact with various systems including information management, embedded, process control, and communications systems.
9.1.2: Describe the different process models (e.g., waterfall, iterative, and agile).
9.1.3: Provide an example illustrating the phases of a software lifecycle and its deliverables.
9.1.4: List several examples of software risks.
9.1.5: List the key components of a use case.
9.1.6: Analyze a given requirements model for a simple software system.
9.1.7: Describe the fundamental techniques used for requirements elicitation.
9.1.8: List the key components of a data model (e.g., class diagrams or ER diagrams).
9.1.9: Specify functional and non-functional requirements for a software system.

# SKU 9.2

**Software Design, Construction, Verification and Validation**

Topics:

1. Design principles: coupling and cohesion, and encapsulation.
2. Mechanisms for implementing designs to achieve desired properties such as reliability, efficiency, and robustness.
3. Integration strategies including top-down, bottom-up, and sandwich integration.
4. The process of analyzing and implementing changes to code base developed for a specific project.
5. Program validation and verification.
6. Inspection of medium-size code segments.
7. Types and levels of testing (unit, integration, systems, and acceptance).
8. Techniques for identifying significant test cases for integration, regression and system testing.

SLOs:

9.2.1: Explain design principles such as coupling and cohesion, and encapsulation.
9.2.2: Use a design paradigm to design a simple software system.
9.2.3: Construct models of the design of a simple software system.
9.2.4: describe the software architecture design of a simple software system
9.2.5: Describe mechanisms for implementing designs to achieve desired properties such as reliability, efficiency, and robustness.
9.2.6: Describe integration strategies including top-down, bottom-up, and sandwich integration.
9.2.7: Distinguish between program validation and verification.
9.2.8: Perform an inspection of a medium-size code segment.
9.2.9: Create and document a set of tests for a medium-size code segment.
9.2.10: Use a defect-tracking tool in a small software project.
